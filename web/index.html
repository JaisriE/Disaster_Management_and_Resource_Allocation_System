About the System

This Disaster Management Resource Allocation System is an emergency control room platform engineered for the fictional Aruvi district during severe cyclone crises. It continuously prioritizes incoming incident reports, evaluates physical road reachability across flooded corridors, and recommends optimal allocations of food kits, medicine kits, rescue response teams, and shelter places. The core operational principle ensures that automation supports rather than replaces human command, requiring an authorized officer to confirm or reject every recommended allocation.

The Problem It Solves

  • Severe village neglect: Without systematic ranking, highly affected villages with critical casualties or large populations risk being overlooked in favor of first-come or less urgent calls.
  • Conflicting promises & race conditions: In a manual control room, two officers can inadvertently promise the same depot stock or the same rescue team to different locations, causing fatal shortages.
  • Impassable road routing: Severe storm damage, broken bridges, and flooded highways can sever transit corridors; dispatching relief without real-time road validation leads to stranded convoys and wasted transit time.
  • Static urgency in dynamic crises: New incident reports arrive continuously while conditions evolve; static queues fail to elevate newly critical reports above older, milder incidents.

How It Works

  1. Field Incident Entry: A field officer logs an incident report specifying affected region, severity (1 to 5), impacted population, and requested resources.
  2. Validation & Persistence: The system validates input ranges (non-negative stock, positive population, valid ratings) and persists the report to MySQL.
  3. Deterministic Ranking: Requests are inserted into a priority queue ordered strictly by higher severity first, higher population on ties, and earlier arrival sequence as the final tie-breaker.
  4. Network & Inventory Verification: The system evaluates transportation graph reachability using BFS and DFS, and calculates shortest travel times from staging depots using Dijkstra's algorithm.
  5. Algorithmic Recommendation: A deterministic allocation plan is generated, determining full or partial supply allocation and explicitly accounting for outstanding deficits.
  6. Officer Decision Authorization: A command officer inspects the recommended route and quantities, then explicitly confirms the allocation or rejects it with a mandatory reason.
  7. Transactional Database Update: Upon confirmation, inventory deductions, shelter reservations, team assignments, and audit logging are executed within an atomic ACID transaction.
  8. Automatic Re-Prioritization: Any subsequent state change (stock update, road closure or reopening, severity or population amendment) automatically re-evaluates and re-prioritizes all remaining waiting requests.

Key Features

  • Deterministic priority queue ranking (Severity > Population > Arrival Order)
  • BFS and DFS transportation network reachability analysis to detect isolated communities
  • Dijkstra minimum-time route computation using min-heap priority structures
  • Partial allocation accounting with outstanding demand tracking
  • Strict non-negative resource inventory invariants preventing negative stock
  • Duplicate allocation prevention blocking repeat confirmations on fulfilled requests
  • Shelter overbooking safeguards enforcing physical capacity limits
  • Interactive road closure and reopening with immediate graph recalculation
  • Immutable operational audit logging for every system and officer action
  • Relational MySQL persistence ensuring complete recovery across server restarts

Technologies Used

  • Core Language: Java with basic object-oriented programming (encapsulation, inheritance, polymorphism)
  • Data Structures: Weighted Graph (adjacency list), Min-Heap PriorityQueue, HashMap, ArrayList, HashSet
  • Algorithms: Breadth-First Search (BFS), Depth-First Search (DFS), Dijkstra's Shortest Path Algorithm
  • Database & Connectivity: MySQL 8, JDBC with PreparedStatements and atomic transactions
  • Frontend: Semantic HTML5, Vanilla CSS (CSS variables, flexbox, grid), Vanilla JavaScript (zero external dependencies, 100% offline)

Sustainable Development Goals (SDG) Alignment

SDG 3 (Good Health and Well-Being): Rapid medical and trauma supply dispatch within minutes, preventing secondary infections and post-disaster morbidity.
SDG 9 (Industry, Innovation & Infrastructure): Dynamic graph algorithms (BFS reachability, Dijkstra shortest paths) adapt instantaneously to bridge and highway closures.
SDG 11 (Sustainable Cities & Communities): Shelter overbooking protections and fair, deterministic priority ranking prevent resource hoarding in vulnerable settlements.
SDG 13 (Climate Action): Pre-positioned inventory allocation minimizes emergency vehicle fuel consumption and carbon footprint during severe cyclone events.
